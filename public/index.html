    Overview

    The Firefly III AI Categorizer automatically classifies withdrawal transactions using an LLM (OpenAI, Gemini, DeepSeek, or a locally hosted model via Ollama). When Firefly III records a new withdrawal, it sends a webhook to the categorizer, which determines the best category and writes it back — all without manual intervention.

    Key features:

    • Real-time webhook processing — new withdrawals are classified automatically as they are created.
    • Multiple AI providers — OpenAI, Google Gemini, DeepSeek, or any OpenAI-compatible endpoint (Ollama, Azure, etc.).
    • Three-outcome model — the AI tells you whether it is confident (CLASSIFIED), unsure (ASSUMED), or cannot classify (NEEDS REVIEW).
    • Web UI dashboard — real-time job monitoring, transaction browser, review queue, and full settings management.
    • Batch operations — classify all uncategorised withdrawals at once, or re-classify any selection of transactions.
    • History-aware classification — past categorised transactions are sent to the AI as examples. Repeated transactions from the same merchant are auto-matched without an AI call.
    • Destination account matching — the AI can also set the expense account (payee) for each withdrawal, and transactions miscategorised as "Transfers" can be converted into real transfers.
    • In-UI configuration — no need to restart; settings are saved through the web interface and persist across restarts.
    Security note: This application has no built-in authentication. Do not expose it directly to the internet. Run it on a private network or behind a reverse proxy with authentication (e.g. Nginx basic auth over HTTPS).

    Setup

    1 Run the server

    The recommended way is Docker Compose:

    services:
  categorizer:
    image: ghcr.io/openaccountants/firefly-iii-ai-categorize:latest
    restart: unless-stopped
    ports:
      - "3000:3000"
    volumes:
      - ./categorizer-data:/data
    docker compose up -d

    Then open http://localhost:3000. You will be taken to the Settings page.

    2 Connect to Firefly III

    In Settings → Firefly III Connection, enter your Firefly III URL and a Personal Access Token. To create a token, go to your Firefly III profile, open the OAuth tab, scroll to Personal Access Tokens, and click Create new token. Give it a name and copy the token — it is shown only once.

    Click Test connection to verify, then Save settings.

    3 Configure an AI provider

    In Settings → AI Provider, choose a provider and enter your API key.

    • OpenAI — create a key at platform.openai.com/api-keys. Default model: gpt-4o-mini.
    • Google Gemini — get a key at aistudio.google.com. Default model: gemini-2.5-flash.
    • DeepSeek — create a key at platform.deepseek.com. Default model: deepseek-chat.
    • Local (Ollama) — select OpenAI as the provider, set the Base URL to your Ollama endpoint (e.g. http://localhost:11434/v1), leave the API key blank, and set the model name.

    Click Save settings when done.

    4 Set up the Firefly III webhook

    In Firefly III, go to Automation → Webhooks and click Create new webhook. Set the URL to http://<host>:3000/webhook and save.

    Note: Only withdrawal transactions without an existing category are processed. All other events are acknowledged and ignored.

    5 (Optional) Enable destination account matching

    In Settings → Behaviour, check Set destination account automatically. When enabled, the AI will also attempt to match or create an expense account (payee) for each withdrawal processed via webhook. On the Transactions page you can always choose whether to classify categories, set destinations, or both — regardless of this setting.

    Using the application

    Jobs

    The Jobs tab shows a live feed of all classification activity. Each row shows the destination, description, amount, assigned category, and outcome. Click any row to expand and see the AI's reasoning, the raw prompt and response, and any assumptions it made.

    The summary bar at the top shows counts for each outcome.

    Transactions

    The Transactions tab lets you browse all withdrawals. Use the date range and filters to narrow the list. Select one or more transactions, then use the Actions dropdown to:

    • Set Category & Tags — run the AI classifier for the category (and suggest tags when tag suggestion is enabled).
    • Set Destination — run the AI to match or create an expense account.
    • Set Both — classify the category and match the destination in one pass.

    Use Select all to operate on every transaction in the current date range.

    Filters let you narrow by missing category, missing destination, a specific category or destination name (e.g. (no name)).

    Review

    The Review tab collects transactions the AI could not handle confidently. It shows groups for Needs Review, AI Assumed, and Destination Assumed. Each card has a category dropdown and a searchable destination account field. Click Apply to write your decisions back to Firefly III. Use Skip to defer a group to the end of the queue.

    The Convert to Transfers section shows withdrawals miscategorised as "Transfers". Select a destination asset account and click Convert to Transfer to replace the withdrawal with a proper transfer.

    The Review tab auto-refreshes every 30 seconds while you are on it.

    Categories

    The Categories tab shows all categories from Firefly III that are visible to the AI. Categories with notes show their descriptions. The "Transfers" category is highlighted — transactions assigned to it are flagged for conversion on the Review page.

    Accounts

    The Accounts tab shows your expense accounts from Firefly III. These are the accounts the AI can match payees against when destination matching is active. You can refresh the list with the button in the top-right corner.

    Settings

    The Settings tab is where you configure everything. Changes are saved to disk and take effect immediately without restarting. The Behaviour section lets you customize the tag prefix, provide additional context to the AI (e.g. "I have no business expenses"), and toggle destination matching. The Advanced section exposes tuning parameters for history context, worker concurrency, and batch throughput.

    The three-outcome classification model

    Every classification produces one of three outcomes:

    CLASSIFIED
    The AI is confident. The category is set and the transaction is tagged <prefix>:classified.
    ASSUMED
    The AI is unsure but applies a conservative default. The category is set, the transaction is tagged <prefix>:assumed, and the AI's assumption is written to the notes. These appear on the Review page for confirmation.
    NEEDS REVIEW
    The AI cannot classify this transaction. No category is set. The transaction is tagged <prefix>:needs-review and appears on the Review page for manual categorization.

    The AI follows a conservative principle: when in doubt between two categories, it picks the one that is less favourable to you (e.g. personal over business expense). This way an incorrect ASSUMED classification does not mistakenly claim a deduction.

    When destination matching is enabled, the destination confidence is independent of the category confidence. A transaction can be CLASSIFIED for its category but ASSUMED for its destination — or vice versa.

    Destination account matching

    When destination matching is active, the AI also determines the expense account (payee) for each withdrawal:

    • MATCH — the AI finds an existing expense account that corresponds to the merchant and links the transaction to it.
    • CREATE — the AI is confident a new account is needed and creates it in Firefly III automatically. CREATE is only attempted when the destination confidence is CLASSIFIED.

    On the Review page, each review card includes a searchable destination account field. Typing a name that does not match any existing account shows a NEW badge, indicating a new expense account will be created when you apply.

    The Convert to Transfers section shows transactions categorized as "Transfers". These are withdrawals that should actually be transfers between your own asset accounts. Select the destination asset account and the categorizer converts the withdrawal into a proper transfer, showing the source account so you can verify the direction of the transfer.

    Batch & transaction operations

    The Transactions page is the central place for bulk operations:

    • Filter by date range, missing category, missing destination, or a specific category/destination name.
    • Select individual transactions, a full page, or all transactions in the current period.
    • Use the Actions dropdown to run the AI on the selection with your choice of category-only, destination-only, or both.
    • Monitor progress on the Jobs tab — each transaction becomes a job tracked in real time.

    You can also run a one-off batch from the command line: 

    ./firefly-ai-categorize --batch

    This classifies all uncategorised withdrawals and exits without starting the web server.

    How it works

    POST /webhook  (Firefly III sends new transaction)
        │
        ▼
  Validate: withdrawal, no existing category
        │
        ▼
  Fetch history: recent categorised transactions (few-shot examples)
        │
        ▼
  Fetch categories from Firefly III
        │
        ▼
  (Optional) Fetch expense accounts (destination matching)
        │
        ▼
  Send to LLM with three-outcome prompt
        │
        ├── CLASSIFIED    → set category + tag ":classified"
        │                    └── destination → MATCH existing or CREATE new
        ├── ASSUMED       → set category + tag ":assumed" + assumption
        │                    └── destination → MATCH existing or CREATE new
        └── NEEDS_REVIEW  → tag ":needs-review", no category set
                             └── destination → may still be assigned

    Results are written back to Firefly III with fire_webhooks: false to prevent re-triggering. When destination matching is enabled, the flow also fetches expense accounts and the LLM attempts to match or create a destination (expense) account alongside the category. Destination confidence is independent of category confidence — a transaction can be CLASSIFIED for its category but ASSUMED for its destination, or vice versa.

    Repeated transactions from the same merchant benefit from history-based matching: when enough past transactions agree on the same category and destination, the AI call is skipped entirely. This reduces latency and API costs for recurring payments.

    Batch mode: Run ./firefly-ai-categorize --batch to classify all uncategorised withdrawals and exit without starting the web server. Use the Transactions tab in the UI for selective batch operations with control over whether to classify categories, set destinations, or both.
